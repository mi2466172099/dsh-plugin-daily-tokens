# dsh-plugin-daily-tokens

在 [DeepSeek Harness](https://github.com/deepseek-ai)（DSH）窗口左上角**红绿灯旁边**逐位滚动显示今天消耗的 token 总量，例如 `今日 12.34M token`。

## 安装

1. 把本仓库放到任意目录；
2. 打开 DSH → **插件** → **添加插件**，选择这个目录；
3. 稍等一秒，红绿灯右侧出现 `今日 … token`。

注意：**Host 侧代码改动不会热更新**，改完 `index.js` 需要到「插件」页把这一行关掉再打开（不必重启应用）；只改 `client.js` 刷新页面即可。

## 要求

- DSH 0.2.x（`shell.overlay` 插槽与 `session/event` 事件）。
- 无需任何 API 密钥：数据来自本机会话日志。

## 数据来源

OpenCode 等厂商的用量接口只给百分比，不返回 token 数，所以这里统计的是 **DSH 自己记录的消耗**：

- 扫描 `$DSH_HOME/sessions/**/session*.jsonl(.zstd)`；
- 取 `assistant/message` 事件里的 `usage`（`inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens`）；
- 按事件时间过滤到本机当天 00:00 之后，全部模型累加。

## 删除会话不会让数字变小

OpenCode 等厂商的用量接口不给 token 数，所以这里统计的是 DSH 自己的消耗。**如果只依赖会话日志，删掉会话（进回收站、甚至清空回收站）后重启插件，那个会话当天的用量就会消失。**

因此插件把当日累计**独立持久化**：

- 位置：`$DSH_HOME/daily-tokens/<当日 00:00 的毫秒时间戳>.json`（默认 `~/.dsh/daily-tokens/`）；
- 内容：当日累计计数 + 已计入的消息水位（`sessionId:seq` 去重表）；
- 写入：事件提交后防抖 5 秒落盘（`temp + rename` 原子写），插件卸载时强制刷盘；
- 读取优先级：**持久化值 vs 日志重算值取较大者**，所以日志被删只会让"重算值"变小，不会拉低显示；
- 去重：日志覆盖到的位置用水位标记，避免重载后把日志里已有的消息再累加一次；
- 清理：只保留今天和昨天的文件，更早的自动删除。

代价：会多一个几 KB 的 JSON 文件（`seen` 水位裁剪到最近 5 万条）。

## 怎么做到“实时但不耗性能”

Host 侧维持一个内存里的当日累计值，两条数据来源：

1. **事件流**：监听 `session/event`（提交后立即派发），遇到 `assistant/message` 就把它 `data.usage` 累加进去——不碰磁盘。
2. **首次基线**：插件加载后第一次读取时扫一遍会话日志，作为今天已发生部分的起点；之后只有跨天才会再扫。

扫描期间到达的事件先缓冲，扫完按 `(sessionId, seq)` 去重后再补入，所以不会重复计数。实测：

| 场景 | 耗时 |
|:--|:--|
| 首次 read（基线扫描若干日志，约 10 MB） | 约 300 ms |
| 之后每次 read（纯内存） | **0 ms** |
| 一条 `assistant/message` 事件 | 累加，0 ms |

因此客户端可以每 1 秒读一次而几乎不产生成本（窗口隐藏时暂停）。

会话日志本身是 zstd 多帧追加：扫基线时按帧边界记录已解码字节偏移，末尾未写完的帧会解码失败并被跳过，偏移停在上一个完整帧边界，下次再读。

| 场景 | 实测耗时 |
|:--|:--|
| 冷启动全量扫描（7 个日志 / 11.1MB） | 277 ms |
| 整文件重新解码（3.6MB / 2215 帧） | 100 ms ← 若每次刷新都这么做，会卡住 Host |
| **增量刷新（新增 0.16MB / 120 帧）** | **6 ms** |
| 日志无变化 | 0 ms |
| 整体结果缓存 | 800 ms |

末尾未写完的帧会解码失败并被跳过，偏移量停在上一个完整帧边界，下次再读。

## 显示与刷新

- 位置：窗口标题条、红绿灯右侧（`position: fixed`，`left: 80px; top: 15.5px`，与红绿灯中心对齐，水平间距 18px）；不拦截鼠标，不影响拖动窗口和点红绿灯。
- 排版：`今日` 用 11px、`--dsw-alias-label-secondary` 70% 透明度；数字用 12px、字重 500、等宽数字，整体属于 chrome 级次要文字，不与会话标题抢视觉。
- 刷新：挂载时读一次，之后每 1 秒一次（窗口隐藏时跳过）；Host 侧是纯内存读取。
- 数字滚动：**逐位滚轮**。每一位数字是一个 0–9 的竖直列，数值变化时该位用 CSS `transition`（**700ms**）滚到新数字（中间会扫过沿途的位），未变化的位不动；同一量级下小数位固定，所以只有进位时才整体重排。
- 变化脉冲：整块数字在每次变化时上浮 1px 并提亮到主文字色，320ms 后回落——即使只有最后一位在滚，也能一眼看到“刚刚变过”。
- `prefers-reduced-motion: reduce` 下两者都取消。
- 由于该元素 `pointer-events: none`，鼠标悬停不会弹提示；完整的输入 / 输出 / 缓存明细放在 `aria-label` 里。
- 统计失败时显示"今日 token 统计不可用"，而不是留空。

## 限制

- 统计范围是本机 DSH 的会话日志：你在 OpenCode 桌面端、其它客户端或别的机器上的消耗不在内。
- 只统计已提交到会话日志的 assistant 消息；正在流式输出、尚未落盘的部分要等下一轮刷新。

- 位置是相对窗口左上角固定的；侧边栏收成窄条时，红绿灯位置不变，所以标记仍对齐，但它可能贴近会话标题区。
